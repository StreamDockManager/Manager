Using Vault entries

Reference a saved value without storing it in the action or macro itself.

Get started

  1. Unlock Vault, then open Entries and select Add entry.
  2. Open a supported built-in action in the Device editor or select a step in a macro.
  3. Paste the reference in a supported field, or pick an eligible entry with Choose from Vault where available. Save your binding or macro.

Your action reads the current value at run time. The saved reference stays the same when you replace the value in Vault.

Copy a reference example

To copy a personal entry’s reference, choose Copy reference in Entries. Use it only in fields that support that entry type.

Replace <vault-id>.<entry-id> with the full Entry ID shown in Entries, not its name.

Text fields that accept references

Put a reference on its own or alongside other text. You can use the same references in individual built-in actions and in macro steps.

  • Type text, Paste text, Set clipboard: text.
  • Show notification, Input prompt: title and message.
  • Action menu: title and choice labels.
  • Icon, label & live display: display titles, canvas Label text, and authored live-label text. The editor keeps the reference; live pixels use the current unprotected value.
  • Insert date and time and Clipboard slots: the date format and the slot name. Date replacements are literal text.
  • Conditional action and Wait for condition: literal text comparisons, process names, and one unprotected File or Folder reference for an exact local path.
  • Write file: contents, not the destination path.
  • Open website, Open link, Search selection: the path, query or fragment after a fixed HTTP or HTTPS website. Values are URL-encoded. Only use entries you want to share with that website.

Use Choose from Vault in the action editor to insert at the caret or replace selected text. Insert run outputs is not needed for Vault references. It controls run-output placeholders such as ${run.name} .

Where each type works

Entry type Supported use
Text, Integer, Boolean Unprotected values appear as normal text, whole numbers, or true and false .
File or Folder path Unprotected entries can appear as text. To open the location in Reveal file , use one eligible reference as the entire path or choose it from Vault.
JSON Unprotected entries appear as compact JSON in text fields. To compare clipboard JSON with a Vault entry, use Matches Vault JSON in a Conditional or Wait for condition action.
Location An unprotected location appears as latitude,longitude . Add .name , .latitude , or .longitude before the closing brace to insert just that field. Matches Vault JSON is a separate comparison and rounds coordinates to two decimal places.
API key, Bearer token, Other secret Not expanded in built-in text fields. A supported plugin can request access to an eligible entry for a specific action. Review the access in Vault → Access.

Insert or replace a reference

To switch entries, replace the whole reference. The rest of the text can stay. Consider where the result will appear before using an unprotected value in a notification, clipboard, menu, or file.

If you see ${vault.unlinked} in an imported field, use Choose from Vault where available, or copy a local reference from Entries and replace the placeholder. Live desktop actions insert nothing for missing, invalid, locked, or protected references in ordinary text fields. Macro previews and debug runs do not read Vault values; the live display canvas does render eligible unprotected text.
